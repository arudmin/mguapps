# Правила разработки MGU Apps

## Ветки
- top-chart — текущая разработка Chrome Dino; main — стабильная версия. Не переносить код в main без явного указания владельца.
- Не менять согласованные параметры физики, дизайн Dashboard и блокировку игры при движении без явной задачи.

## Обязательное документирование
- Для каждой задачи Chrome Dino в том же коммите (или в той же серии коммитов до публикации) обновлять apps/chrome_dino/README.md: дата, версия, изменения, исправления, тесты, известные ограничения и статус проверки на реальном BMW.
- При пользовательских изменениях обновлять также корневой README.md, включая актуальную версию и краткий список нововведений. Сохранять структуру общего README из main, информацию о других приложениях и установке.
- История версий — от новых к старым; не стирать предыдущие записи. Документационные изменения фиксировать в записи текущей версии без изменения версии приложения. Не придумывать отсутствующие данные.
- При изменении версии согласовать app.json, package/package.json, package/npm-shrinkwrap.json, package/javascript/kit/app-spec.json и package/rhmiData/application.json; обновить ссылки на версию и тесты.
- Проверять GitHub Actions после push. Отделять успешный CI и имитацию MGU от реальной установки и измерений FPS на BMW. Не утверждать, что тест прошёл, пока нет подтверждения. Обновлять журнал проверки при получении результата.
- Экспериментальные функции, включая онлайн-рейтинг, явно обозначать как неготовые до интеграции и тестов.

## API и сервер
- Версии игры, сервера и API независимы. Совместный пуш по явной просьбе владельца допустим.
- Поддерживать только актуальный API v1; удалять устаревшие реализации, сохранять историю в документации и данные пользователей. Мигрировать постоянную очередь безопасно. Документировать контракт, авторизацию, ошибки, повторную отправку и кеш в apps/chrome_dino/leaderboard/API.md и историю сервера в README.md.
