# Chrome Dino 1.5.36 · SDD

## Архитектура

Клиент BMW MGU ID7/ID8 использует существующие Dashboard, контроль стоянки и локальные настройки рекордов. Он передаёт сетевые запросы через HTTPS-транспорт рейтинга и хранит очередь синхронизации и состояние восстановления в `dino-outbox.json` с правами 0600. Диалоги используют те же события сенсорного экрана и iDrive, что и остальные меню. Для новых надписей в пакете есть небольшой атлас символов всех 12 языков. Игровые правила, SDK ACL и сигналы автомобиля сохранены.

Cloudflare Worker 0.2.13 и существующая база D1 используют API v1. Сервер сохраняет прежний UUID игрока, имя, исходное имя, рекорды, операции синхронизации и принадлежность к группе автомобиля. Публичный рейтинг по-прежнему выбирает один лучший результат группы автомобиля для каждой сложности.

## Сценарии

1. В подключённом профиле откройте **Топ игроков → Профиль**. Приложение создаст случайный 32-символьный код и покажет его после подтверждения сервером. Сохраните код отдельно до удаления игры.
2. После переустановки согласитесь на участие в рейтинге и введите код. Клиент прочитает идентификатор автомобиля после согласия и проверит код на сервере. При совпадении откроется окно с прежним именем и четырьмя личными рекордами, включая результаты вне публичной таблицы.
3. **Восстановить профиль** подтвердит подключение прежней записи. Клиент объединит рекорды по максимуму для каждой сложности, запишет имя и поставит итоговые результаты в обычную очередь синхронизации. Код меняется после подтверждения восстановления. Пока окно открыто, клиент сразу показывает новый код. Его также можно посмотреть в рейтинге.
4. **Начать заново** создаёт отдельную установку со случайным UUID и именем `user_xxxxxxxx`. Только текущие локальные рекорды попадают в новый профиль. Прежние аккаунты и рекорды остаются в D1.
5. Старому профилю без сохранённого кода администратор может выдать одноразовый код на 24 часа. Он проверяет владельца и выбирает конкретный профиль. Код вводится через тот же диалог и при первом подтверждении заменяется обычным кодом. Инструкция есть в [README сервера](leaderboard/README.md).

## API и изменения схемы

Точный контракт описан в [API v1](leaderboard/API.md). Пути `/v1/register`, `/v1/sync`, `/v1/leaderboard`, `/v1/name-availability`, `/v1/account` сохраняют прежний формат. Три дополнительных пути создают код, проверяют код и подтверждают перенос. Код и токены идут в теле запроса или заголовке авторизации.

| Таблица | Данные и связи |
| --- | --- |
| `players` | Неизменный UUID, текущее и исходное имя, исходный токен в виде хеша, HMAC идентификатора установки и группы автомобиля |
| `personal_scores` | Личные максимумы, по одной положительной записи на игрока и сложность |
| `sync_operations` | Идемпотентные операции, по ключу игрока и UUID операции |
| `profile_recovery` | Один текущий хеш кода на игрока. Срок действия задан только для временных выдач администратора |
| `recovery_sessions` | Хеш дополнительного токена, UUID игрока и хеши прежнего и нового кодов для безопасного повтора подтверждения |
| `sessions`, `submissions`, `best_scores` | Таблицы прежней модели, сохранённые миграцией |

Миграция `0009_profile_recovery.sql` создаёт две таблицы и индекс без переписывания существующих строк. Привязка нового токена и смена кода идут одной транзакцией D1. Старые токены сохраняют доступ для уже поставленных в очередь операций. Явное удаление профиля удаляет также его коды и дополнительные токены через внешние ключи и не затрагивает другие профили автомобиля.

## Безопасность и конфиденциальность

Чтение автомобиля разрешается при явном согласии, активном окне и подтверждённой стоянке. Исходный VIN используется только внутри клиента. Worker получает SHA-256 по HTTPS и преобразует его прежним HMAC-ключом в идентификатор группы автомобиля. Ни исходный VIN, ни его хеш не дают доступа к профилю без действующего кода. Код генерируется из 128 бит случайности и проверяется вместе с группой автомобиля. Для кода и токена в базе сохраняются хеши. Пользователь получает код в автомобиле или через согласованный частный канал. Публичного административного API нет. Выдача кода требует аутентификации через Cloudflare D1 и доступна владельцу репозитория через ручной workflow. Аналитика отсутствует.

## Ошибки и офлайн

При сбое проверки кода можно повторить запрос или продолжить играть офлайн. Если подтверждение уже поставлено в очередь, приложение сохраняет его локально вместе с новыми учётными данными и повторяет при восстановлении связи. Тот же запрос после потери ответа возвращает тот же профиль. Недействительный или истёкший код не изменяет имя и рекорды. Если клиент получил подтверждение, но завершился до записи настроек, рекорды будут применены при следующем запуске. Офлайн-игра до подтверждения сохраняет текущие локальные рекорды. Для начала восстановления после чистой установки нужны связь, доступный сигнал автомобиля и ранее сохранённый код или выдача администратора.
